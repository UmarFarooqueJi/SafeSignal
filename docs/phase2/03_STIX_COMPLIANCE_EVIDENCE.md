## 1. PRE-REMEDIATION NON-COMPLIANCE AUDIT FINDINGS

An independent acceptance audit of the STIX 2.1 exporter bundle generated by SafeSignal revealed two strict compliance failures against the OASIS STIX 2.1 specification:

```text
[-] Results for: test/stix_bundle_output.json
[X] STIX JSON: Invalid
    [X] relationship--39fb2f1e-fe89-47af-ab99-fe9a8a2b6422: relationship_type: 'hosted_on' contains invalid characters
    [X] relationship--f6971b3f-a212-4b9e-9888-409e22288fd6: relationship_type: 'resolves_to' contains invalid characters
    [X] relationship--613387a7-771a-4083-b238-0150486a0228: relationship_type: 'drops_payload' contains invalid characters
    [!] Warning: bundle--d828d838-3967-4642-ad6d-c9d1d4dde477: {401} Custom property 'spec_version' should be implemented using an extension...
```

### Root Cause Analysis:
1. **OASIS STIX 2.1 Section 3.2 (Relationship Types):** The STIX 2.1 specification mandates that all `relationship_type` values conform strictly to the regex `^[a-z0-9-]+$`. Underscores (`_`) are strictly forbidden in relationship types.
2. **OASIS STIX 2.1 Section 4.1 (Bundle Object):** Unlike STIX 2.0, the STIX 2.1 `bundle` object does **not** contain a `spec_version` property at the root level. Specifying `spec_version: "2.1"` on the bundle causes the validator to treat it as an un-prefixed custom property.
3. **OASIS STIX 2.1 Section 11 (Custom Properties):** Custom properties must be prefixed with `x_` and follow standard naming conventions.

## 2. PHASE 2 SPECIFICATION REMEDIATION

### 2.1 Relationship Type Hyphenation & Automatic Normalization
In `lib/core/forensics/threat_graph_service.dart`, all relationship edges are now normalized upon export:
```dart
final normalizedRel = edge.relationship.toLowerCase().replaceAll('_', '-').trim();
```
Standardized relationship names in SafeSignal include:
- `hosted-on` (links URL to Domain)
- `resolves-to` (links Domain to IP Address)
- `drops-payload` (links URL/Domain to APK package or Hash)
- `indicates` (links Observable to Threat Category)
- `related-to` (general relationship)

### 2.2 Bundle Root Cleanup
Per STIX 2.1 Section 4.1, the root `spec_version` key was removed. Each child SDO (`indicator`) and SRO (`relationship`) explicitly declares `'spec_version': '2.1'`.

### 2.3 Custom Property Prefixing
All forensic ledger metadata keys embedded in the bundle adhere strictly to the `x_` custom property specification:
- `x_safesignal_evidence_chain_verified`: `bool`
- `x_safesignal_evidence_blocks_count`: `int`
- `x_safesignal_observable_type`: `string`
- `x_safesignal_metadata`: `object`
